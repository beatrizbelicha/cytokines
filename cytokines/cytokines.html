2 Distributions and Outliers

2.1 Define the metadata column that separates groups

Here we are assigns the string “condicao” (the name of our clinical metadata column) to the variable condition. This parameterizes the script. By assigning the grouping variable (e.g., controle x câncer) to an object, avoid hardcoding the column name throughout the pipeline. This makes the code dynamic and easily adaptable for future datasets.

condition <- "condicao"

2.2 Identify cytokines columns

colnames() extracts all column names, and ncol() counts the total number of columns. The 12:ncol() indexing subsets the vector of names, selecting only those from the 12th column to the last. Early columns contain categorical metadata, we assume the actual biomarker concentrations begin at column 12. Isolating these names into cytokines_names allows us to apply mathematical transformations exclusively to analytical variables, preventing execution errors on demographic columns.

cytokine_names <- colnames(data.cytokines)[12:ncol(data.cytokines)]

2.3 Correcting from , to .

MAGPIX software often exports numerical data with commas (e.g., 140,5) and out-of-range string (e.g., “OOR<”). R interprets these columns as discrete characters. This specific combination rectifies the decimal formatting (140.5) and forces non-numerical strings into NA. This is an absolute prerequisite for rendering continuous plots and running non-parametric statistical test correctly.

The pipe |> forwards the raw data to mutate, which modifies columns. The acroos function applies a rule simultaneously to all columns specified in cytokine_names. The rule uses gsubs(",", ".", .) to find commas and replace them with dots, followed by as.numeric to coerce the result into a continuous numeric format.

data.cytokines <- data.cytokines %>%
  mutate(across(all_of(cytokine_names), ~ as.numeric(gsub(",", ".", .))))

3 Testing the normality of each cytokine.

3.1 Initialize an empty dataframe to store the final results

normality_results <- data.frame(
  Citocina = character(),
  Condição = character(),
  p_valor = numeric(),
  Distribuição = character(),
  stringsAsFactors = FALSE
)

3.2 Create the loop

Here we need to separate, because testing distinct immunological states within the same sample triggers the bimodal distribution trap, yielding false negatives. The control group and the cancer group do not belong the same biological population.

Part 1: The filter() function acts as a strict subsetting funnel. It scans the rows of our df_temp and creates df_controlcontaining only the patients where the condition column matches “controle”. It repeats this logic for the “cancer” cohort. The filter function guarantees biological isolation prior to testing. Furthermore, R’s native Shapiro-Wilk function strictly requires a continuous numeric vector as its input, not a multi-variable dataframe. - The [[cyt]] indexing extracts the specific cytokine column from the dataframe and coerces it into a pure numeric vector (a simple array of numbers).

Parte 2: In the Shapiro-Wilk framework, the Null Hipothesis (H0) assumes the data is normally distributed. Statistically, a p-value < 0.05 rejects this normality. Automating this logical step with ifelse() eliminates the need for manual interpretation of dozens of p-values, effectively neutralizing the risk of human error in our data pipeline. The script makes the statistical triage.

  • The shapiro.teste() function computes the Shapiro-Wilk mathematical algorithm on our numeric vector.
  • The $p.value suffix acts as a data extractor: the test outputs a larger list of statistics, but we command R to surgically extract only the p-value, storing it in p.value_control ou p.value_cancer. -The ifelse(condition, true, false) function is a logical decision engine. It evaluates the p-value threshold. If p > 0.05, it outputs the string "Normal". If not, it outputs "Não Normal".

Part 3: We create a two-row temporary table (temp_results) containing the cytokine name, the group, the p-value, and the distribution status. Finally, bind-rowsfunction “pastes” these two rows at the bottom of our main table (normality_results).

for (cyt in cytokine_names) {
  # Retrive the cleaned dataframe for the current cytokine from our list
  df_temp <- df_list[[cyt]]

  #--Separating the groups--
  #Filter data by clinical group
  df_control <- df_temp |> filter(.data[[condition]] == "controle")
  df_cancer <- df_temp |> filter(.data[[condition]] == "cancer")

  #Extract purely the numeric vectors for the test
  vec_control <- df_control[[cyt]]
  vec_cancer <- df_cancer[[cyt]]

  #--Shapiro-Wilk Normality Test
  #Run the test and extract only p-value
  p.value_control <- shapiro.test(vec_control)$p.value
  p.value_cancer <- shapiro.test(vec_cancer)$p.value

  #Determine distribution based on the p-value threshold (Alpha = 0.05)
  dist_control <- ifelse(p.value_control > 0.05, "Normal", "Não Normal")
  dist_cancer <- ifelse(p.value_cancer > 0.05, "Normal", "Não Normal")

  #--Consolidating the results--
  temp_results <- data.frame(
    Citocina = c(cyt, cyt), 
    Condição = c("Controle", "Câncer"), 
    p_valor = c(p.value_control, p.value_cancer),
    Distribuição = c(dist_control, dist_cancer), 
    stringsAsFactors = FALSE
  )

  #Append these results to our main general dataframe
  normality_results <- bind_rows(normality_results, temp_results)
}

4 Appling the transformation

Cytokine data commonly follows a right-skewed distribution, with most values clustered at the lower end and a few extreme high values. This violates the normality assumptions required by many parametric statistical tests.

4.1 Log

The transformation in one the most widely used strategies to address the problem of normality, as it compresses the scale of high values and pulls the distribution closer to a normal curve. However. it’s essential to verify whether the transformation was actually effective by comparing the data distribution before and after, for example, using plots or normality test. Applying a transformation without testing it can create a false sense that the assumptions have been met, ultimately compromising the validity of downstream analyses.

This code create a new datarame called data.log from data.cytokines, applying a natural logarithm transformation to all cytokine columns. The pipe operator (|>) passes data.cytokines as the first argument to the next function. The mutate() function, from the dplyr package, modifies or create columns in a dataframe, in this case, it overwrites the selected cytokines columns with their log-transformed values.

The across() function applies a transformation to multiple columns simultaneously, avoiding repetitive column-by-column operations. It takes two arguments:

  1. all_of(cytokines_names), which selects only the columns listed in the cytokines_names vector and raises an error if any name is missing from the dataframe;

  2. ~log(.), an anonymous function where ~ defines the formula and . refers each column being processed, computing the natural logarithm (base e) of every value.

data.log <- data.cytokines |> 
  mutate(across(all_of(cytokine_names), ~ log(.)))

This code creates an empty dataframe called normality_log, which servers as a structured container to store the results of normality tests applied to the transformed data. Each arguments defines a column with it corresponding data type:

  • Transformação = character() and Citocinas = character() store, respectively, the name of the transformation applied and the name of cytokine tested. Condição = character() identifies the experimental group. p_valor = numeric() holds the p-value returned by the test. Distribuição = character() records the conclusion about the data distribution. Finally, stringsAsFactor = FALSE instructs R to keep text columns as character type, preventing them from being automatically converted to factor, which could cause issues when appending new rows to the dataframe.
normality_log <- data.frame(
  Transformação = character(),
  Citocina = character(),
  Condição = character(),
  p_valor = numeric(),
  Distribuição = character(),
  stringsAsFactors = FALSE
)
for (cyt in cytokine_names) {

  dist_cancer <- ifelse(p.value_cancer > 0.05, "Normal", "Não Normal")

  temp_results <- data.frame(
    Transformação = "Log",
    Citocina = c(cyt, cyt),
    Condição = c("Controle", "Câncer"),

    Distribuição = c(dist_control, dist_cancer),

4.2 Log1p

The log() function computes the pure natural logarithm, if any value in the data is zero, the result will be -Inf, which breaks downstream analyses. The log1p() function, on the other hand, computes log(1 + x), adding 1 to each value before applying the logarithm. This ensures that zeros are transformed to log(1) = 0, avoiding the problem entirely. For cytokines data, where zero values are biologically plausible, log1p() is generally the safer choice.

5 PCA

5.1 Raw data

This code creates a matrix called pca.raw.matrix by selecting only the cytokines columns from the dataframe data.cytokines. The dplyr::select() function is called with explicit package notation to make clear which package it comes from and to avoid conflicts with functions of the same name loaded from other packages in the session. The result is a dataframe containing only the raw, untransformed cytokines values, which will be used as input for the Principal Component Analysis (PCA).

The prcomp() function runs a PCA on the raw cytokines data and stores the results in the object pca.raw. The function is R’s built-in PCA implementation and takes the following arguments:

  • pca.raw.matrix: is the dataframe containing only the raw cytokine values, prepared in the previous step;

  • center = TRUE: centers the data by subtracting the mean of each variable, so that all columns have a mean of zero, this is essential to prevent variables with very different means from dominating the principal components;

  • scale. = TRUE: scales the data by dividing by the standard deviation of each variable, giving all of them a variance pf 1. This is particularly important when cytokines are measured on different scales or units, preventing those with numerically larger values from having a disproportionate influence on the analysis. The dot in the argument name is a quirk of the function designed to avoid conflict with R’s base scale() function.

We now prepare the PCA results for visualization by organizing them into a dataframe and extracting the variance explained by each component.

pca.raw$x accesses the scores matrix from the prcomp() output, which contains the coordinates of each sample in the new dimensional space defined by the principal components. The as.data.frame() function converts this matrix into a dataframe, a more convenient format for plotting. A new column called condicao is then added to the dataframe. The pull() function from dplyr extracts a single column from a dataframe as a plain vector — in this case, the column whose name is stored in the variable condition. This allows each point in the PCA plot to be colored or grouped according to the experimental condition of each sample. Finally, summary(pca.raw)$importance returns a matrix of metrics for each principal component, where row [2,] corresponds to the proportion of variance explained. The [1:2] index selects only the first two components (PC1 and PC2), which are the ones that will be plotted. The result is multiplied by 100 to convert to a percentage and rounded to one decimal place using round(..., 1).

Finally, the PCA is plotted using ggplot2. The pca.raw.df dataframe is passed as the base data, and within aes() the aesthetic mappings are defined: x = PC1 and y = PC2 position each sample on the cartesian plane according to its coordinates in the first two principal components, while color = condicao colors each point according to the experimental group of that sample.

  • geom_point(size = 3) adds the points to the plot, with size 3 for better visibility.

  • labs() defines the plot’s text elements, title names the plot, and the x and y arguments dynamically build the axis labels using paste0(), which concatenates the component name with its explained variance from the var.raw vector, producing labels such as “PC1 (32.5%)”.

This block applies a correction for multiple comparisons to the Mann-Whitney test results and updates the significance classification accordingly.

p.adjust(results.mann$p_value, method = "fdr") adjusts the raw p-values using the Benjamini-Hochberg method, also known as the False Discovery Rate (FDR) correction. When multiple statistical tests are performed simultaneously — one for each cytokine — the probability of obtaining at least one false positive increases with each additional test. The FDR method controls the expected proportion of false positives among the results classified as significant, producing adjusted p-values that account for the total number of tests performed. These adjusted values are stored in a new column called FDR in the results.mann dataframe.

ifelse(results.mann$FDR < 0.05, "Sim", "Não") then reclassifies each cytokine as significant or not based on the adjusted p-value rather than the raw one, which is the correct approach after applying a multiple comparisons correction. The result is stored in a new column called Significativo_FDR. It is common to find that some cytokines that appeared significant based on raw p-values lose their significance after FDR correction — this is expected and is precisely the purpose of the adjustment.

results.mann$FDR <- p.adjust(

results.mann$Significativo_FDR <- ifelse(

Spearman correlation coefficient is the most appropriate choice in this case, as it is based on the ranked values of the data and does not assume normality, making it more robust for biological data that frequently presents asymmetric distributions or outliers.

This loop iterates over each cytokine in the correlation matrix and creates an individual dataframe containing only the cytokines that show a strong correlation (above 0.8) with it.

  1. for(cyt in colnames(cancer.matrix)) iterates over the column names of the correlation matrix, where each column represents a cytokine. cor.value <- cancer.matrix[, cyt] extracts the column corresponding to the current cytokine, retrieving its correlation coefficients with all other cytokines.
  2. data.frame(Citocina = names(cor.value), Coeficiente = round(as.numeric(cor.value), 2)) creates a temporary dataframe with two columns: the name of each cytokine and its correlation coefficient with the current cytokine, rounded to two decimal places. as.numeric() ensures the values are treated as numbers.

This allows each cytokine to have its own dataframe of strong correlations without requiring manual naming.

  cor.value <- cancer.matrix[, cyt]
  df_temp <- data.frame(
    Citocina = names(cor.value),
    Coeficiente = round(as.numeric(cor.value), 2),
    stringsAsFactors = FALSE
  )
  df.filter <- df_temp |> 
    filter(Coeficiente > 0.8 & Citocina != cyt)
